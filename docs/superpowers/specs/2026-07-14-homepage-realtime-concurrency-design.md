# 首页实时 API 并发设计

## 目标

精简公开首页，并展示站点当前正在处理的 API 请求总数。

- 删除“已支持的 AI 模型”区域及其下方全部内容，包括现有页脚。
- 保留顶部导航、主视觉、能力标签和三张功能卡片。
- 在三张功能卡片下方增加单项运行指标，只展示“实时 API 并发”。
- 并发口径为当前占用账号并发槽位的 API 请求数，不是在线用户数、QPS、排队数或配置容量。

## 非目标

- 不展示运行时间、成功率、累计 Token、缓存命中率或首字响应速度。
- 不公开平台、分组、账号、用户、API Key、最大容量或排队详情。
- 不将管理员运维接口直接开放给匿名访问。
- 不引入 SSE 或 WebSocket 推送连接。

## 首页界面

状态区位于三张功能卡片下方，参考用户提供的运行指标布局，采用居中、留白充分的单项数据展示：

- 小标题：`实时 API 并发`
- 主数值：当前并发整数，例如 `12`
- 状态：绿色圆点表示数据已成功获取
- 辅助信息：`每 5 秒更新`

首次请求完成前显示 `--`。接口请求失败时保持 `--`，不弹出全局错误提示，并在下一个轮询周期自动重试。深色模式和移动端保持现有首页风格，状态区不使用额外卡片嵌套。

## 数据接口

新增匿名可访问接口：

```text
GET /api/v1/status/concurrency
```

成功响应只包含：

```json
{
  "current": 12,
  "updated_at": "2026-07-14T12:00:00Z"
}
```

接口不接受筛选参数。响应不得包含账号、用户、平台、分组、容量、排队数或 Redis 键信息。

## 后端统计

复用现有 Redis 并发槽位，不重新统计 HTTP 连接，也不查询使用日志：

1. 从账号活跃索引读取尚未过期的账号 ID。
2. 清理这些账号槽位中的过期成员。
3. 批量读取各账号槽位数量并求和。
4. 将总数作为当前 API 并发返回。

账号槽位在实际上游请求处理期间持有，因此该总数与现有管理员并发监控口径一致。统计路径只遍历活跃索引，不扫描全部账户数据库。

服务端对成功的聚合结果缓存 2 秒，避免多个首页访客在同一时刻重复读取 Redis。错误结果不缓存；成功缓存过期后，如果 Redis 不可用，接口返回服务不可用，前端显示 `--`，不继续返回旧数值。

## 前端刷新

- 首页挂载后立即请求一次。
- 成功或失败后均以 5 秒间隔继续刷新。
- 页面进入后台时暂停轮询，重新可见时立即刷新并恢复轮询。
- 组件卸载时清理定时器和可见性事件监听。
- 首页自定义 `home_content` 模式保持现有行为，不加载默认首页状态区。

## 安全与性能

- 匿名接口仅暴露一个非负整数和服务端时间。
- 不复用需要管理员身份的 `/api/v1/admin/ops/concurrency`。
- 服务端短缓存限制 Redis 聚合频率，前端 5 秒轮询限制请求频率。
- 总数至少为 0；异常或无效统计不得返回负值。

## 测试

后端测试覆盖：

- 无活跃槽位时返回 0。
- 多个活跃账号的槽位正确求和。
- 过期槽位不计入总数。
- Redis 错误转换为服务不可用响应。
- 公开接口响应不包含内部明细字段。
- 2 秒缓存避免重复聚合，并在过期后重新计算。

前端测试覆盖：

- 首页不再渲染支持模型区域和页脚。
- 首次加载显示 `--`，成功后显示并发整数。
- 请求失败时显示 `--` 且不触发全局错误提示。
- 每 5 秒刷新，页面隐藏时暂停，恢复可见时立即刷新。
- 卸载时清理定时器和监听器。

验证包括相关 Go 单元测试、前端 Vitest、TypeScript 类型检查和生产构建。

## 部署

该改动同时涉及后端接口和嵌入式前端，需要生成新的自定义版本镜像，并沿用现有单服务替换流程部署。PostgreSQL、Redis 和排行榜服务不重建，不执行数据迁移。
