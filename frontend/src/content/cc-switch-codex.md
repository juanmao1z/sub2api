# CC Switch 配置 Codex

通过 CC Switch 为 Codex 添加 `zhouz.online` 自定义供应商。配置完成后，Codex 会使用你的中转站密钥和对应分组调用模型。

> 配置和切换供应商前，请先完全退出 Codex。这样可以避免 Codex 正在运行时覆盖配置文件。

## 开始前的准备

你需要准备以下内容：

1. 在[密钥管理](/keys)中创建一个 API 密钥，并为密钥选择可用分组。
2. 从 [CC Switch Releases（点击下载）](https://zhouz.online/downloads/CC-Switch.exe) 下载并安装 CC Switch。
3. 安装 Codex，并至少正常启动过一次。
4. 确认中转站 API 地址为 `https://api.zhouz.online/v1`。

> API 地址末尾必须包含 `/v1`。只填写根域名会导致连接测试失败。

## 配置流程

整个过程分为四步：

1. 在 CC Switch 中新增 Codex 供应商。
2. 填写 API Key、API 地址和模型。
3. 检查自动生成的 Codex 配置。
4. 测试连接并启用新供应商。

## 第一步：新增供应商

打开 CC Switch，切换到 **Codex** 页面，然后点击右上角的添加按钮。

选择 **自定义配置**，填写一个便于识别的名称，例如 `zhouz.online`。建议始终新增配置，不要直接覆盖已有供应商，方便出现问题时快速切回。

## 第二步：填写连接信息

在供应商表单中填写：

| 配置项 | 填写内容 |
| --- | --- |
| API Key | 你在 Sub2API 密钥管理中创建的密钥 |
| Base URL | `https://api.zhouz.online/v1` |
| 模型 | 当前密钥分组支持的模型 |

API Key 属于敏感信息，不要发送给他人，也不要放进截图、公开文档或聊天记录。

如果不确定应该选择哪个模型，请先返回控制台检查密钥所属分组及其可用模型。不同分组的价格、并发和可用模型可能不同。

## 第三步：检查 Codex 配置

保存供应商后，CC Switch 会为 Codex 生成或更新 `auth.json` 和 `config.toml`。

检查下面三点：

- `base_url` 指向 `https://api.zhouz.online/v1`。
- 当前启用的供应商是刚刚创建的 `zhouz.online` 配置。
- 模型名称属于密钥分组当前支持的模型。

不要把完整 API Key 复制到工单或公开截图中。排查问题时只保留开头和结尾少量字符。

## 第四步：测试并启用

先使用 CC Switch 的连接测试功能。测试通过后，再启用这个供应商并重新打开 Codex。

启动 Codex 后发送一个简短请求，确认能够正常返回内容。随后可以到[使用记录](/usage)检查是否产生了对应请求。

## 常见问题

### 测试提示 401

通常表示 API Key 无效、已经删除，或者复制时包含了多余空格。重新从密钥管理创建密钥后再测试。

### 测试提示 403

检查密钥状态、所属分组和模型权限。密钥存在但没有对应模型权限时，也可能返回 403。

### 地址无法连接

确认 Base URL 完整填写为 `https://api.zhouz.online/v1`，并检查系统代理、防火墙或 DNS 是否拦截了请求。

### 模型不可用

返回控制台查看当前分组支持的模型，然后在 CC Switch 中改成对应模型。不要只根据其他教程里的示例模型填写。

### 启用后 Codex 仍使用旧配置

完全退出 Codex，再在 CC Switch 中重新启用供应商。如果仍未生效，先切换回原供应商，再重新启用 `zhouz.online`。

### 请求提示 429

429 通常表示并发数、请求频率或上游容量达到限制。等待正在运行的请求结束后重试，并检查控制台中的并发使用情况。

## 安全建议

- 每个设备或用途使用独立密钥，便于单独停用和审计。
- 不要在教程截图、群聊、代码仓库或录屏中暴露完整密钥。
- 怀疑密钥泄露时立即删除旧密钥并创建新密钥。
- 遇到问题时记录时间、模型、请求类型和错误码，不要提交完整密钥。
