# Kedaya 前端 UI 融合范围

## 授权与边界

本次融合以 `.pi/plan/kedaya-前端-ui-融合实施计划-20261010-0130.md` 为准，实施对象为 `sub2api-custom/frontend` 的原生 Vue 源码。改动限定在前端布局、样式、展示元数据和必要的展示交互适配；不改变后端 API、数据库、认证、权限、功能开关、计费、支付、风控、模型转发或业务规则。

本次部署授权来自用户在实施完成后的明确指令，仅执行应用服务切换，不修改后端源代码或生产配置。

## 已融合

- 控制台 Kedaya 风格侧栏、顶部栏、内容区、折叠和移动端菜单。
- 用户态仪表盘、API 密钥、使用记录、渠道状态、可用渠道、订单、兑换、邀请返利、个人资料和订阅页面的视觉与容器融合。
- 管理员仪表盘、运维、用户、分组、订阅、账号、渠道定价/监控、代理、兑换码、优惠码、公告、用量、审计、风控、Prompt 审计、插件、支付管理、邀请返利和设置页面的视觉融合。
- 模型广场、公开密钥用量查询、法律阅读页、安全页控件和已有条款弹层外观。
- 深浅色主题、顶部栏控件、通知、表格页和选定页面的加载/空态/反馈样式。
- 充值中心仅调整金额输入和快捷金额区域；支付方式、摘要、提交、SDK、回调和支付状态结构保持原实现。
- `App.vue` 展示作用域与构建装配隔离，确保选定源码页面不被保留页面的快照样式污染。

## 保留与延期

- 登录、注册、首页主体样式保持原样。
- `/recharge`、批量图像主体、无限画布、工单、支付结果、二维码、Stripe、Airwallex 等支付流程页不做主体重设计。
- 原有路由、API 方法、请求字段、权限判断、功能开关、简单模式、自定义菜单、字段校验和业务操作全部保留。
- `kedaya-review` 仅作为视觉参考；其账号、角色切换、模拟 API、演示支付和合成数据没有进入正式前端。
- 未验证的原站管理员会话、真实支付、生产账号写入和原站未实现流程不作为已验证能力声明。

## 文件边界

正式改动位于 `sub2api-custom/frontend`，包括现有 Vue 页面/布局组件、三个 Kedaya 作用域样式文件、UI 融合工具与测试，以及 `kedaya/assemble.mjs`、`kedaya/runtime/bootstrap.js`、`kedaya/verify.mjs`。没有修改 `workspace.json`、`sub2api-leaderboard` 或后端源码。
