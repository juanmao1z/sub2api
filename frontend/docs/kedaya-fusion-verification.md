# Kedaya 前端 UI 融合验证记录

## 验证环境

- 项目：`sub2api-custom/frontend`
- 目标：本地源码构建与隔离 fixture 预览
- 视口覆盖：`1440x1000`、`768x1024`、`375x812`
- 主题覆盖：light、dark
- 角色覆盖：user、admin（隔离测试会话）
- 隔离预览：本机 `127.0.0.1`，外部请求由浏览器检查拦截；临时 fixture、截图和日志均保存在会话 scratch 目录，不进入正式前端。

- 页面范围包括用户控制台、管理员已选页面、模型广场、公开密钥用量、法律阅读、安全页控件、保护页和支付流程入口。
- 构建产物的原生入口、首页边界、快照样式隔离、启动脚本语法和资源校验通过。

## 目标交互检查

已确认或验证：

- 顶部主题切换在 light/dark 间切换，并同步 `localStorage` 与根节点主题类。
- 未认证访问 `/dashboard` 仍重定向 `/login`。
- 移动端控制台使用菜单按钮打开侧栏和遮罩，关闭后路径不变。
- API 密钥创建弹层保留名称、厂商、分组、额度等字段和原提交路径；隔离 fixture 能渲染可用分组。
- `/purchase` 金额区保留快捷金额与自定义金额绑定；支付方式、摘要和提交结构未替换。

最后一组自动化交互脚本在执行器层面两次被中止，未将其失败误记为页面失败。诊断已确认中止前主题与保护路由通过；移动侧栏、密钥创建和金额区已通过独立 DOM/请求诊断确认结构。完整浏览器矩阵仍是本轮页面验收依据。

## 未验证与限制

- 原站仅验证过普通用户身份，没有声称通过原站管理员会话验证；管理员页面为参考设计下的本地真实源码 UI。
- 没有执行真实充值、退款、转账、密码重置、线上账号修改或生产业务写入。
- Stripe、Airwallex、二维码支付、回调、轮询和外部 SDK 的真实服务行为未在生产环境验证；隔离环境仅验证页面结构与现有生命周期。
- 隔离非支付页面可能尝试加载 Airwallex SDK，浏览器检查会阻断外部请求；正式应用未加入 SDK 阻断逻辑。
- Browserslist、动态 import 和 bundle size 警告仍为既有构建提示，不构成新增错误。

## 改动边界

- 未修改 `workspace.json`、`sub2api-leaderboard`、后端源码、数据库、锁文件或生产配置。
- 未把 `kedaya-review` 的账号、模拟 API、角色切换或合成数据编入正式前端。
- 本地验证完成后，按用户明确追加的部署指令只切换 `sub2api`，保留 PostgreSQL、Redis、leaderboard 和数据目录。
