# Agent Note: v0.2.21 ARM64 升级与生产部署

Status: implemented

## Problem

生产基线为自定义 v0.2.19（5d90cdf6566e1159f3598475bab513bce0d5c2a5），用户要求适配并部署官方 v0.2.21。官方标签提交为 10ba8f9b4dc2e6023d4a9879ab77b21841babd10，VERSION 仍为 0.2.20，Go 要求 1.27.3。必须升级后端而保留原始公开页、固定控制台、工单、计费及出站私网策略。

## Decision

合并已核实的完整 v0.2.21 标签，明确项目版本为 0.2.21，目标 linux/arm64。workspace.json 同时记录官方原始版本和自定义发布版本。两个 Dockerfile 继续使用 Go 1.27.3，主构建 Node 24 与 pnpm 9.15.9 不变。代理与镜像源仅通过当前命令传入。

公开页、固定控制台及构建配置保持前次发布的文件内容：/login、/home 和根地址沿用历史布局，国际化在构建时预编译，保持严格 CSP。合并时 Git 把新增官方前端误判为移动到 public-pages 的文件，按当前 HEAD 清单恢复前端并保留有意删除，不让官方源码重写历史公开页。依赖注入同时接入新 MCPOAuthHandler 和本地 TicketHandler。画布、指南、渠道颜色及出站私网 socket 校验保留。

新增三个迁移：249_add_usage_logs_api_key_cost_index_notx 为用量日志建立并发覆盖索引，249_mcp_oauth 新增三张授权表，250_openai_cache_write_ttl 新增 30m/12h token 和 nullable 12h 价格列。迁移以完整文件名为账本键，历史 SQL 与 checksum 不改写。新版没有新增必需生产变量；MCP_PUBLIC_URL 未配置时不启用 MCP。固定控制台不自动增加 MCP 授权/管理、TTL 计费详情、图像尺寸分流和新配额刷新页面；新增后端响应字段与原有前端兼容。内存预算配置键为 gateway.request_body_memory_budget_bytes，默认按检测的最小内存上限的四分之一与 1GiB 下限自动选择。

新增上游回归依赖的共享测试夹具从同一标签恢复，不删断言或伪造辅助函数。版本迁移测试通过 migrationFilesThrough 固定基线，兼容 006b 等历史文件名前缀；旧 v0.2.19 用例仅执行至 248，本次用例验证 306→309。真实副本测试仅接受 restore_v0221_ 开头的数据库，检查历史校验和、关键表行数、索引有效性、TTL/MCP schema、重复迁移及旧账本兼容。

发布使用清洁合并提交、不可变标签及绑定版本/源码/架构的镜像。正式写入已由本次用户请求授权。切换前在服务器受限目录保留 PostgreSQL 备份并实际恢复验证；只重建 sub2api，保留 PostgreSQL、Redis、leaderboard 及数据，核验公网 /health、原始公开页、保留服务 ID 和新迁移。正式产物摘要、部署与页面证据写入 deploy-artifacts/<release>/release.json。

## Alternatives considered

直接使用官方镜像可以快速获得新版全部 UI，但会替换原始公开页和现有控制台及后端定制，因此构建定制合并版本。只挑选部分修复可降低合并工作量，但无法完整覆盖官方版本行为及迁移，因此合并经核实的完整标签并保留既有前端删除。放宽 CSP 能绕过旧国际化编译器问题，但会削弱现有安全策略，继续采用已验证的构建时文案预编译。

## Consequences

官方后端更新与定制界面、工单和出站策略共存，代价是固定前端需要后续单独适配新增 UI。共享测试夹具增加源码体积，但让新增回归覆盖可编译并保留原断言。用量日志索引可能延长其他数据规模实例的首次启动，本次副本耗时不能替代线上健康检查。应用镜像回滚不撤销 schema 和数据变更，备份恢复是独立数据恢复手段；不自动开启 MCP 或改写生产站点设置。
