# Agent Note: v0.2.22 ARM64 升级与生产部署

Status: implemented

## Problem

生产当前为自定义 v0.2.21，源码提交 0dddb51e630596cf396ab504f9af3f15db55db44，包含删除社群弹窗后的历史公开页与固定 Kedaya 控制台。用户明确要求适配并部署官方 v0.2.22。官方标签 b0fa9f3e6eeab1968a53e1289b69daa4bb40ca2b 的 VERSION 仍为 0.2.21，Go 要求 1.27.4；新增两个 251 前缀迁移，需保留历史账本及数据。

## Decision

合并固定 v0.2.22 标签，显式设置项目发布版本 0.2.22、Go 1.27.4，目标 linux/arm64。保留当前 frontend 整棵树及固定资源契约，历史首页继续没有社群入口和弹窗。保留工单、计费、出站私网安全拨号与严格 CSP。旧控制台省略 force_openai_ultrafast 时后端保留已有值，新组默认为 false；MCP 继续默认关闭。官方 UsageBillingLaneCombiner 构造、传递与退出 Stop 同现有 TicketHandler 接线共存。

HTML 缓存同时保留项目原有的设置 TTL、标题/图标注入和故障回退，并统一正常缓存与回退响应的 no-store 头和 CSP nonce 规则；带 nonce 的请求即使匹配 ETag 也返回当前 nonce 的 HTML，避免缓存文档同 CSP 不匹配。新增回归覆盖过期缓存刷新失败仍保留品牌且使用新 nonce。官方新增测试依赖的共享夹具从同一标签恢复，保留断言；历史 v0.2.21 升级测试固定迁移终点 250，防止后续增量使其预期漂移。

新增迁移保留官方完整文件名和内容，生产基线 309 项迁移升级为 311 项。切换前创建权限受限的 PostgreSQL custom-format 备份，实际恢复并在独立副本执行迁移，检查历史 checksum、关键表行数、工单、Ultra Fast 字段、日汇总状态和重复迁移。保留现有数据库，不回写生产设置。

发布使用干净提交、不可变标签、带版本和源码 revision 的 ARM64 镜像。用户已授权上线；只重建 sub2api，核验 PostgreSQL、Redis、leaderboard 容器 ID 不变及公网健康、页面和资源摘要。备份、迁移、测试、镜像及浏览器证据保存至 deploy-artifacts 对应发布目录。

## Alternatives considered

直接使用官方镜像可更快部署全部新功能，但会替换现有界面与后端定制，因此合并源码构建。仅挑选修复可缩小改动，但不能完整覆盖发布的调度、扣费及数据库契约，因此使用固定官方标签。整体恢复官方新前端可直接提供新增管理 UI，但会覆盖用户指定的历史公开页和当前控制台，因此保留固定前端，并明确新增后端配置需要后续单独接入 UI。

## Testing

前端构建、类型与集成/导航 18 项、画布 4 项、发布回归 15 项通过。Go 1.27.4 后端 unit、vet、嵌入前端及服务接线检查覆盖本次合并。隔离 PostgreSQL 验证 303→306、306→309、309→311 历史升级；生产备份实际恢复得到 309 项迁移、604 位用户、4 张工单、486745 条用量日志，真实恢复副本的 309→311 升级约 0.40 秒，关键表行数与 checksum 保留、重复执行和旧账本兼容，新 Ultra Fast 默认关闭、日汇总字段/函数存在，临时库与测试程序清理。生产镜像、资源、页面、保留服务和健康检查记录于发布目录。

## Consequences

本次获得官方调度、扣费和流式兼容改进，同时保留用户既有页面和定制行为。恢复测试夹具增加源码体积，但让官方新增回归真实编译执行。日汇总状态和触发器修改涉及数据库锁与账本，副本迁移验证不替代线上健康和迁移核查。镜像回滚不会撤销数据库迁移，备份必须保留。固定控制台不会自动获得 Ultra Fast、Vertex 多区域等官方新增管理 UI，相关后端 API 可用；本次不自动启用新策略或改写生产站点设置。

## Test isolation

v0.2.22 副本测试使用独立 UPGRADE_V0222_CLONE_TEST_DSN，避免与历史副本的命名安全断言共用环境变量。官方计费内存回归测量进程级 HeapAlloc，服务包单独通过、完整套件曾超出 8 MiB 阈值约 60 KiB，目标用例独立连续五次通过；该用例改为在独立测试子进程执行原测试体，保持随机模型数量、数据库调用检查、快照调用检查及 8 MiB 阈值不变，避免其他用例遗留 goroutine 影响全进程堆读数。仅重跑目标用例虽更省改动，但不能稳定保证整套测试的隔离，因此采用子进程边界。
