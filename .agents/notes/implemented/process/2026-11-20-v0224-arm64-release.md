# Agent Note: v0.2.24 ARM64 升级与生产部署

Status: implemented

## Problem

生产基线为自定义 v0.2.23，提交 c8a0937acf08adc0986eb8b9555a1ad48a1da5cb。用户要求适配并部署官方 v0.2.24。固定标签为 5c2982a81b46e2142d0143d2f83c1ce9c4da1d24，其 VERSION 仍为 0.2.23。新版涉及请求字段歧义拒绝、工具搜索、流式及缓冲响应兼容、新用户默认平台配额；需保留固定控制台、历史公开页、渠道倍率透传、工单、计费和出站地址校验。

## Decision

合并固定 v0.2.24 标签，显式发布版本 0.2.24，继续采用 Go 1.27.4 和 linux/arm64。frontend 整棵树与升级前逐字节相同，保留上一版装配层的 ultrafast_multiplier 载入保存透传，首页仍无社群入口或弹窗。工单接线、计费组合器、严格 CSP 缓存 generation 与出站私网拨号校验继续保留。NewAdminService 接入官方新增的 UserPlatformQuotaRepository，保留构造和退出清理契约。

保留官方请求字段校验：重复 JSON 字段即使取值相同也返回 400，相关大小写别名、嵌套字段、multipart 和 WebSocket 帧按官方协议校验；检查发生在模型白名单之后、合成路由和计费之前。标准对象序列化不产生重复键，不需要对固定控制台绕过校验。保留按入口选择文本请求体上限及合成模型改写。Codex 上下文支持官方新增的 untrusted_content、ide_context、proposed_plan 和 output 类型规则。

默认平台配额只在创建新普通用户时快照，包括管理员创建用户；不回填现有用户。快照脱离调用方事务，失败保持 best-effort，不阻塞注册。MCP、Ultra Fast 和搜索供应商不自动启用，不改写生产设置。

新版修改过的后端测试采用相同标签版本，依赖的 OAuth 刷新及 Astra Pro/Responses failover 共享测试文件也从同一标签完整恢复，保留其断言。直接删除失败测试可减少维护成本，但会丢掉配套回归，因此保留同版本夹具和测试体。

数据库无新增或改写迁移，账本保持 312 项。生产切换前创建权限 600 的 PostgreSQL custom-format 备份并实际恢复；新的 TestV0224UpgradeProductionClone 在受限命名的临时库中连续两次运行 ApplyMigrations，比较账本、关键表行数，以及用户、分组、工单、价格、配额和设置摘要。摘要只用于比较，不输出私有字段。仅重建 sub2api，保留 PostgreSQL、Redis、leaderboard 的容器和数据目录。

发布绑定清洁源码提交、不可变标签、版本与架构元数据、二进制和归档 SHA256。浏览器检查真实公开路由但不提交登录、OAuth、支付或模型请求。资源检查将本次 Docker 前端阶段输出与正式二进制及线上文件关联；证据保存在 deploy-artifacts/0.2.24-arm64-20261120。

## Related decisions

检索活跃笔记后，[v0.2.23 发布](../../implemented/process/2026-11-18-v0223-arm64-release.md) 与本篇部分重叠，保留其渠道倍率透传及迁移依据；本篇承接新增运行时行为。[历史公开页](../../implemented/feature/2026-10-28-restore-public-pages.md)、[删除社群入口](../../implemented/simplification/2026-11-12-remove-community-dialog.md)、[出站私网策略](../../implemented/bug-fix/2026-10-13-url-private-host-policy.md) 和 [v0.2.22 缓存失效](../../implemented/process/2026-11-17-v0222-arm64-release.md) 是独立保留约束。本篇接管同主题 proposed 草稿，没有其他需废弃的提案。

## Alternatives considered

官方镜像能缩短发布过程，但会替换现有前端和后端定制，因此合并源码构建。整体恢复官方前端可以直接获得新的账户及搜索管理界面，但会丢失固定公开页和控制台，故保留当前 frontend 并验证兼容边界。仅挑选部分修复可缩小源码变化，却不能完整覆盖请求解析、工具搜索与响应转换契约，因此合并不可变发布标签。跳过重复字段校验可以兼容存在歧义的旧请求，但会使计费与转发解析结果可能不一致，故保留官方校验并明确客户端行为变化。

## Testing

Go 1.27.4 完整 `go test -count=1 -tags=unit ./...`、`go vet -tags=unit ./...` 与 unit+embed 的 web/server 测试通过。新用户配额 fail-open、重复字段拒绝、工具搜索和响应兼容由官方回归覆盖。

前端构建、类型与 19 项集成/导航/倍率往返检查、4 项画布测试和 15 项发布回归通过。隔离 PostgreSQL 的受限管理员权限回归及 303→306、306→309、309→311、311→312 历史迁移链通过。生产备份 176141063 字节，SHA256 为 60a818ce986fadf2b233bc3c5f10ccd20a2988ccad65192883793c47da0979c6；实际恢复得到 312 项迁移、606 位用户、4 张工单和 506556 条用量记录。ARM64 恢复副本的重复启动迁移检查约 0.29 秒，账本、关键数据、配额与设置保持不变。

## Consequences

本次获得官方请求解析、搜索与模型兼容修复，同时保持现有 UI 和配置。客户端必须避免重复字段，包含等值重复及有关大小写别名；新默认配额仅适用于新用户。固定控制台不会自动出现官方新增管理控件。备份必须保留，应用镜像回滚不替代数据库恢复。验收证据中的迁移保持 312→312，不能描述为新增迁移或主动更新现有用户配额。
